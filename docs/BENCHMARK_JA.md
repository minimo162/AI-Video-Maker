# 変化検出の精度ベンチマーク（手順書）

アプリは録画全体を走査し、画面が変わった時刻と場所を自動で求めて出来事画像を作ります。この手順では、**正解の操作表**とアプリの**出来事一覧**を比べ、検出の精度を数値にします。Copilot も社内PCも要りません（Edge での所要時間を測る場合だけ、Edge が要ります）。

> **状況（2026-10-15）**：比べる道具と合成データでのテストは用意しましたが、**実際の録画ではまだ1度も測っていません**。下の「記録」の欄は空です。

## 出す値

| 指標 | 意味 |
|---|---|
| 再現率／取りこぼし率 | 正解の操作のうち、±1秒以内に検出した変化がある割合／ない割合 |
| 適合率／誤検出率 | 検出した変化のうち、±1秒以内に正解の操作がある割合／ない割合 |
| 途中の状態の捕捉率 | 正解表で `intermediate=1` の操作（ダイアログ内の選択など）のうち、±1秒以内に画像がある割合 |
| 時刻のずれ | 一致した操作について、最も近い出来事の時刻 − 操作の時刻（中央値・絶対値の平均・最大） |
| カーソル検出率 | 正解の操作に一致した出来事のうち、変化直前のカーソル位置が見つかった割合 |
| 走査時間 ÷ 録画の長さ | アプリが表示する「所要 ○分○秒」を入れた場合だけ |

数え方の決まり：

- 「検出した変化」は、出来事一覧の種類が「局所」と「全画面」のものです。**一定間隔の全画面**（全体の流れを見せるために一定間隔で入れる画像）、**指定時刻**、**カーソル周辺**の画像は数えません。一定間隔の時刻は、アプリと同じ計算（録画の長さ÷20、8〜150秒）で求めて除きます。
- 一致は1対1ではありません。1つの操作の近くに出来事が2つあっても、両方とも「正解に一致」と数えます。
- 途中の状態は、次の変化の直前に撮るので、操作から最大で一致の幅（1秒）遅れることがあります。

## 用意するもの

機密を含まない画面で、Snipping Tool などで録画を3本作ります（提案の P1-2）。

1. Excel の操作 3分（セル入力、数式、リボン、「形式を選択して貼り付け」などのダイアログ）
2. Web の申請画面 3分（入力欄、プルダウン、ボタン、画面の切り替え）
3. 両方が混ざった10分

録画ごとに、正解の操作表を CSV で作ります。動画プレーヤーで1操作ずつ止めて、操作した時刻を0.1秒単位で書きます。

    time,kind,target,intermediate
    3.2,クリック,B2セル,0
    5.0,入力,B2セルに=SUM(C2:C9),0
    12.4,クリック,ホーム>貼り付け>形式を選択して貼り付け,0
    14.1,選択,ダイアログの「値」,1
    15.3,クリック,ダイアログのOK,0

- `time`：操作した瞬間の元動画の秒（必須）
- `kind`・`target`：記録用の文字。採点には使いません
- `intermediate`：ダイアログやメニューの中で選んだだけの状態（その後に閉じる・確定する操作が続くもの）なら `1`
- `#` で始まる行はコメントです

## 手順

1. アプリ（`index.html`）で録画を読み込み、「出来事画像を作る」を押します。終わったら、表示された「所要 ○分○秒」をメモします。
2. 「Copilotに相談して、場面を作る」の「コピーする中身を見る」を開き、依頼文をすべてコピーします。
3. `tools/benchmark.html` を開き、正解の CSV と依頼文を貼り付け、所要時間を入れて「比べる」を押します。
4. 記録欄の文章に録画名と環境（例：社内PC・Edge 130・1920×1080・拡大率125%）を書き足し、`VALIDATION.md` に貼ります。

ブラウザーを使わずに比べることもできます。

    node tools/benchmark.cjs 正解.csv 依頼文.txt --scan-seconds 95 --recording "Excel 3分" --environment "社内PC Edge"

## 結果の使い方（提案の受け入れ基準）

- 採用するパラメーターで、**再現率90%以上、途中の状態の捕捉率80%以上**。走査時間は録画の長さの**50%以下**を目標にします（Edge の実機で測ります）。
- 縮小の大きさと区画（今は 256×144 に縮めて 16px 区画、閾値は平均差6）を変える案は、このベンチマークで比べてから採用します。
- カーソル検出は、Copilot の手順の正確さに効くと示せた場合だけ残します。

## 合成データでの確認（tests/benchmark.test.cjs）

実録画の代わりに、256×144 の合成フレームを0.5秒ごとに作り、アプリと同じ `frameChange` → `eventCaptures` を通して比べています。

- セル入力・メニューの開閉・ダイアログ内の2回の選択・全画面の切り替えの8操作を、±3の画素ノイズがあっても**すべて検出し、誤検出は0**。ダイアログ内で選んだ2つの状態も画像に残ります。
- 縮小後に 2×2 px（1080p の録画ならおよそ 15×15 px）しか変わらない操作は**検出できません**（区画の平均差が閾値を下回るため）。数文字の入力やセルの選択枠の移動が、実録画で同じように取りこぼされるかは、実録画で測る必要があります。

合成データには、H.264 の圧縮ノイズ、ClearType の文字、画面の拡大率、マウスカーソルの動きがありません。**合成データの結果を実録画の精度とみなさないでください。**
